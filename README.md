# Учебная платформа — Hibernate / JPA

REST-приложение для управления учебными курсами, пользователями, домашними заданиями
и тестами. Стек: Java 17+, Spring Boot 3.5, Spring Data JPA / Hibernate, PostgreSQL,
Maven, Springdoc OpenAPI / Swagger UI. В тестах используется H2.

## Быстрый запуск

Нужны JDK 17 или новее и запущенный Docker с Docker Compose.
Отдельно устанавливать Maven не требуется: в проекте есть Maven Wrapper.

```bash
docker compose up -d --wait
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev,demo
```

Windows: вместо `./mvnw` используйте `mvnw.cmd`.
В IntelliJ IDEA откройте `pom.xml` как Maven-проект, выберите JDK 17+ и запустите
`LearningPlatformApplication` с активными профилями `dev,demo`.

После запуска:

- Swagger UI: [http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html)
- OpenAPI JSON: [http://localhost:8080/v3/api-docs](http://localhost:8080/v3/api-docs)
- Курсы: [http://localhost:8080/api/courses](http://localhost:8080/api/courses)

База создаётся Hibernate автоматически (`ddl-auto=update`). Данные PostgreSQL
сохраняются в Docker volume между запусками. `docker compose down` останавливает БД
и сохраняет данные. Приложение останавливается через Ctrl+C.

## Конфигурация

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `DB_URL` | `jdbc:postgresql://localhost:5432/learning` | JDBC URL приложения |
| `DB_USERNAME` | `learning` | Пользователь БД и `POSTGRES_USER` в Compose |
| `DB_PASSWORD` | `learning` | Пароль локальной БД и `POSTGRES_PASSWORD` в Compose |
| `DB_PORT` | `5432` | Порт PostgreSQL на хосте в Compose |
| `SERVER_PORT` | `8080` | HTTP-порт приложения |

Это демонстрационные параметры для локального запуска. Свою конфигурацию задавайте
переменными окружения. При изменении порта Compose измените также `DB_URL`:

```bash
DB_PORT=5433 docker compose up -d --wait
DB_URL=jdbc:postgresql://localhost:5433/learning ./mvnw spring-boot:run -Dspring-boot.run.profiles=dev,demo
```

Переменные пользователя/пароля Compose применяются при первоначальном создании
БД в пустом volume; изменение переменных не меняет существующего пользователя БД.

Профили:

- `dev` — профиль по умолчанию, форматирование SQL;
- `demo` — добавляет пример данных в пустую БД;
- `test` — H2 в памяти, создание и удаление тестовой схемы; используется тестами.

Запуск без предзаполнения: `./mvnw spring-boot:run`. Для собственной PostgreSQL
создайте БД и пользователя и передайте параметры через переменные окружения.
Docker в таком случае не нужен.

## Демонстрационные данные

Профиль `demo` создаёт все данные одной транзакцией и пропускает загрузку,
если уже есть пользователи, курсы, категории или теги. Повторный запуск не
дублирует данные и не сбрасывает изменения. Для проверки используйте пустую БД.

| Объект | Данные |
|---|---|
| Преподаватель | `teacher@example.com` |
| Студенты | `alice@example.com`, `bob@example.com` |
| Профили | По одному у каждого пользователя |
| Курс | «Основы Hibernate и JPA», категория «Программирование», теги Java и JPA |
| Контент | Два модуля, два урока, два задания без дедлайна |
| Записи | Оба студента записаны на курс |
| Решение | Алиса сдала первое задание, оценка 85/100 |
| Тест | Два вопроса: одиночный и множественный выбор; результат Алисы 2/2 |
| Отзыв | Оценка Алисы 5/5 |

Борис ещё не сдавал задания и тест: его можно использовать для самостоятельной
проверки API. Сценарий сдачи задания рассчитан на первый запуск: повторная сдача
того же задания тем же студентом вернёт `409`. Для повторной проверки создайте
другого студента или выберите второе задание. ID получайте из ответов `/api/users` и `/api/courses`;
на фиксированные числовые значения ID рассчитывать не следует.

## Пример работы через Swagger

API содержит 43 операции. Профили, теги и отзывы входят в ORM-модель и демоданные,
но не имеют отдельных REST-маршрутов.

1. Выполните `GET /api/users` и найдите ID Бориса и преподавателя по email.
2. Выполните `GET /api/courses`. В ответе есть модули, уроки и задания с ID.
3. Отправьте `POST /api/assignments/{id}/submissions`:

   ```json
   {"studentId": 3, "content": "Моё решение"}
   ```

4. Сохраните ID решения из ответа и выполните `PATCH /api/submissions/{id}/grade`:

   ```json
   {"teacherId": 1, "score": 90, "feedback": "Хорошая работа"}
   ```

5. Возьмите `quizId` из модуля в ответе курса и получите тест через
   `GET /api/quizzes/{id}`. Возьмите ID вопроса и вариантов
   из ответа. В `POST /api/quizzes/{id}/submissions` передайте выбранные варианты:

   ```json
   {"studentId": 3, "answers": {"1": [1], "2": [3, 4]}}
   ```

Числа в примерах условные: замените их ID из своей БД. Ключи `answers` — ID вопросов,
массивы значений — ID выбранных вариантов. Правильные ответы API получения теста
не раскрывает; результат вычисляется сервером.

6. Проверьте работу через `GET /api/users/{id}/submissions`, результат теста — через
   `GET /api/users/{id}/quiz-submissions`. ID здесь — ID Бориса.
7. Список студентов доступен через `GET /api/courses/{id}/students`, курсы студента —
   через `GET /api/users/{id}/courses`.
8. Чтобы отписать студента, выполните
   `DELETE /api/courses/{courseId}/enrollments/{studentId}`. Его решения и результаты
   сохранятся и будут доступны по тем же маршрутам.

Для нового студента сначала создайте пользователя с ролью `STUDENT` через
`POST /api/users`, затем запишите его через `POST /api/courses/{id}/enrollments`
с телом `{"studentId": <ID пользователя>}`. Демостуденты уже записаны на курс.

## Бизнес-правила

- Преподаватель курса имеет роль `TEACHER`, записывается на курс `STUDENT`.
- Пара «студент–курс» уникальна. Новая запись имеет статус `ACTIVE`.
  Статус `COMPLETED` поддерживается сервисом; отдельной REST-операции его изменения нет.
- Сдавать работы и проходить тесты можно только при активной записи.
- На задание допускается одно решение студента; после дедлайна сдача запрещена.
- Проверять работу может преподаватель соответствующего курса. Балл от 0 до `maxScore`.
- У вопроса минимум два варианта и хотя бы один правильный; у `SINGLE_CHOICE`
  правильный вариант ровно один. Для `MULTIPLE_CHOICE` требуется полное совпадение
  множества ответов. За правильный вопрос — один балл, за остальные — ноль.
- Вопросы разрешено пропускать; повторные прохождения сохраняются отдельно.
- `timeLimit` — необязательная длительность теста в минутах; таймер и учёт
  времени начала попытки в этой версии не реализованы.
- Тест с результатами нельзя менять или удалять; максимальный балл задания
  с решениями менять нельзя.
- Сервис отзывов проверяет запись студента на курс, уникальность отзыва и оценку 1–5.
  Отзывы демонстрируются в демоданных и интеграционных тестах.
- Отписка сохраняет решения, результаты и отзывы. Курс с этими данными или записями
  студентов удалить нельзя. Удаление пустого курса каскадно удаляет его контент,
  сохраняя общих пользователей, категории и теги.

Аутентификации нет: ID передаются в запросах, роль и принадлежность проверяет
бизнес-логика. Это учебный API, проверка личности пользователя не реализована.

## Архитектура

| Пакет | Назначение |
|---|---|
| `entity` | 15 JPA-сущностей, перечисления и базовый ID |
| `repository` | Spring Data JPA и запросы к БД |
| `service` | Транзакции и бизнес-правила |
| `web/controller` | REST-маршруты и HTTP-коды |
| `web/service` | Транзакционная сборка DTO для API |
| `web/dto` | Отдельные запросы с валидацией и ответы |
| `web/config` | Настройка OpenAPI |
| `web/ApiExceptionHandler` | Общая обработка ошибок |
| `config` | Загрузка демоданных |

Модель: User, Profile, Category, Course, Enrollment, CourseModule, Lesson,
Assignment, Submission, Quiz, Question, AnswerOption, QuizSubmission, CourseReview,
Tag. `course_tag` — таблица M:N, отдельной JPA-сущности для неё нет.

REST API охватывает основные учебные сценарии. Профили, теги и отзывы
демонстрируют ORM-связи через демоданные, сервисы и тесты; отдельных
REST-операций для них нет. Категории доступны для создания и чтения.

Связи настроены с `LAZY`, Open Session in View отключён. DTO собираются внутри
транзакций, поэтому API не сериализует Hibernate-прокси и циклические связи.
Ключевые уникальности и внешние ключи проверяются также на уровне БД.

## HTTP-коды и ошибки

Создание: `201` и заголовок `Location`; чтение/изменение: `200`;
удаление без тела: `204`.

- `400` — неверный JSON, ошибка валидации или бизнес-правила;
- `404` — объект не найден;
- `409` — дубликат или операция конфликтует с зависимыми данными.

Ошибки возвращаются как `application/problem+json`: `status`, `title`, `detail`,
`instance`; для валидации полей добавляется словарь `errors`.

## Тестирование и сборка

```bash
./mvnw test
./mvnw verify
```

Тестам не нужны Docker или PostgreSQL: отдельный профиль подключает H2 в памяти
в режиме совместимости с PostgreSQL. Проверяются CRUD, связи и каскады,
ограничения БД, запись студентов, оценивание работ, подсчёт тестов, REST,
валидация, Swagger и повторный запуск демозагрузчика. Сквозной HTTP-тест
демоданных проверяет поиск реальных ID, сдачу и оценивание работы, прохождение
теста и сохранение результатов после отписки студента. Совместимость с настоящей
PostgreSQL проверяйте запуском приложения с Compose; H2 её полностью не заменяет.

Отчёты Maven Surefire: `target/surefire-reports/`. Собранное приложение:

```bash
java -jar target/learning-platform-0.0.1-SNAPSHOT.jar --spring.profiles.active=dev,demo
```
